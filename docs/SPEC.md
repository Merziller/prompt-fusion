# Prompt Fusion 0.3 — 实现规格与已知产品缺口

作者 Merziller。日期2026-11-26（Asia/Shanghai）。输入基线：指定历史会话的真实需求、三个固定提交与历史报告；以及用户对首版“大面积设置面板”的明确反馈。私人会话与调查脚本只存 .local，不进入公开交付。

## 范围与验收

- R1 非空 UTF-8 文本，输入48KiB、输出80KiB；类型/枚举/上下文均有上限。只增强提示词，无执行原任务的工具。
- R2 原文逐字保留，不删改代码、数字、路径、语言或否定约束。append 保留原文前缀；structured 把原文放在“任务需求”，后续按执行、交付核验、保真边界编排。补充从属于原文，不虚构事实或新增技术/预算/日期等硬约束。中英文有组织指引；其他语言保留。
- R3 高级 API 保留领域、模式、强度与 layout；DSH 不展示这些选择，固定 auto + smart + deep。按输入关键词匹配已审核的插件/界面/API/数据/计划/研究/写作/协作要点，最多五项。模型不得降低结构化请求要求的深度。
- R4 共用零依赖核心；API 默认离线，DSH 单按钮默认使用当前宿主模型选择规则并离线回退，服务商可能计费。模型只返回严格 JSON 规则ID，不自由重写或回答原任务。取消、超时、空值、错误和越界输出可报告/回退。
- R5 DSH 仅在 conversation.input.right 放一个增强按钮。一次点击直接写回草稿，不发送。忙碌时同一按钮停止，完成后同一按钮撤销；编辑、换会话、发送、版本变化时不覆盖。普通文本整篇原生插入；存在原生引用时只追加，避免移动引用位置。没有设置面板、语音按钮或末尾光标要求。
- R6 DSH 只处理当前草稿，不自动读取上下文、文件或上一稿，不在前端装入录音模块。用户继续使用宿主原生语音。高级 API 的显式有界上下文、词典、单列语音整理与既有实验性转写接口保留，但不在输入区展示或后台启动；实体语音未测。
- R7 按能力而非品牌接入：CLI/stdin/单请求JSON、MCP stdio、无状态JSON响应的MCP Streamable HTTP、REST/OpenAPI、自包含标准Skill。八个品牌路径只是快捷预设，任意标签可通过显式skillsDir安装；已有文件不覆盖，卸载核对回执与哈希。Grok Bot、WorkBuddy、Kimi、Muse及豆包工作分别记录文档证据与待测状态；Zcode或未来品牌同样按能力判断，无品牌黑白名单。无TLS/OAuth/旧SSE实现，不默认部署公网服务。
- R8 Apache-2.0，保留上游 MIT/Apache 文本与 NOTICE。独立实现，未直接复用运行代码/模板/图标，原作者只列来源与致谢。

## 架构与取舍

共用core + structure + provider；CLI、两种MCP、REST和DSH调用相同核心。本轮用户复核证明：R2的“逐字保留”和规则模板虽符合旧工程规格，却没有满足自然语言规范改写的真实目标。模型仅选ID、structured合并默认规则、关键词误分类与模板冗余均已公开。0.2文字评分约61/100；0.3仅改接入，不把接口改善当成质量修复。后续真正改写的验收建议见QUALITY_AUDIT，尚未实现或宣称通过。

DSH 界面精简是0.2显式决策：模式/强度/场景内置；参考资料与记忆不自动开启；语音交回宿主；停止与撤销复用同一按钮。API高级功能继续保留以支持跨平台场景。
