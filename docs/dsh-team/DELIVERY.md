## 0.5.1 当前交付

用户已确认本地修复，并授权正式推送和更新。此次交付保留 `Prompt Fusion` 极简名称、全部公开接口和单按钮外观；加入禾杨智绘工作室出品、Merziller开发及双版权署名。Apache-2.0正文与 `THIRD_PARTY_NOTICES.md` 逐字保持；没有把上游作者列为当前开发贡献者。

正式源码已按构建→测试→检查顺序完成384项回归，另用官方MCP SDK六种连接/模型替身组合和React/Lexical原生契约夹具验证。当前运行模块与已测0.5.1-dev仅核心版本字面量不同；独立归档、远端CI、GitHub Release与市场状态以[发布记录](../RELEASE.md)的实际回执为准。8条保留宿主结果不是新质量评分，已登录GUI仍单列未测。

以下保留前期研发与质量演变，不以历史评分冒充本次发行成绩。

2. 用户确认GitHub账号Merziller、公开Gmail及发布操作，同意排除Zcode；后续要求按能力支持更多智能体，而不是品牌白名单。
3. 0.1独立实现共用核心、离线规则和预览；0.2按实际反馈压缩为唯一的增强/停止/撤销按钮。仍保留原句并追加规则的设计没有满足真正改写的目标。
4. 0.3扩展标准Skill、CLI、MCP stdio/Streamable HTTP和REST/OpenAPI。0.3.0 CI真实发现macOS根目录别名误拦，0.3.1修复限定系统映射，保留失败结果。历史源码、发布包和回执见[发布记录](../RELEASE.md)。
5. 四插件历史48份输出复核给出本项目约60.8分，明确承认规范改写不足。这是作者评审、另一量尺，没有新模型调用，不与后来匿名模型分数混报。见[历史审计](../QUALITY_AUDIT.md)。
6. 用户要求保持唯一按钮的现有外观、真正语义改写、每轮与三原插件同口径对照，达到两组≥95、单例≥90且零关键错误后再交付。本轮0.4按[冻结协议](../evaluation/OPTIMIZATION_PROTOCOL.md)执行。

## 逐轮修复

- R1：真正改写后均分超过95，但出现整体长度约束变为正文限制、组件提及变为修改范围、对话门槛和角色排他等七条关键问题，未通过。
- R2：精简并强化范围保持；严格JSON格式与审查返回选择出现两条生成失败，失败计零；其余关键问题仍阻断验收。
- R3：通过`prompt:null`明确选择原候选、一次格式修正恢复协议可靠性。96份生成全部有效，均分99.46仍因新增“而不是先向我提问”未通过。
- R4：增加对修改稿的再次复核与新增对话限制检查。保留四臂共34次上游502故障；还发现擅自断言用户尚未确定技术方案，未通过。
- R5：区分“原稿没提到”与“用户不知道/未决定”，增加窄范围事实捏造检查。96份生成有效，完整评审99.10分仍因指定周末复盘未通过；余额不足造成的缺失评审在原通道恢复后补齐，失败记录保留。
- R6：增加固定星期的新增/丢失检查。完整评审98.85分仍因新增禁止结论、缩窄技术选择禁令未通过。
- R7：保留否定条款原有措辞与作用范围，发现普通词“分别”、阿拉伯语并列否定和中立标签的三种误报；三个失败保留零分，总体86.73，未通过。
- R8：修复上述解析误报；96份生成有效、总体99.38，但仍把整封邮件150字限制缩窄为正文150字，未通过。
- R9：增加数量、单位和适用对象绑定，以及非排他职责保护；正确整体长度限制被检查器误拦，失败保留零分，总体95.38、最低0，未通过。
- R10：修复“全文（包含主题和正文）”的语法归属，保持正文限定与后续局部限定检查。96份新输出、48份有效匿名评审；固定99.79、迁移99.13、总体99.46、最低95、关键错误0，达到冻结门槛。两次传输失败只补齐原请求，早期九轮失败全部保留。308项工程回归另行通过，不计入文字质量分数。

原始请求、失败、输出、匿名顺序、分项理由和冻结运行时均保留在[证据目录](../../evals/semantic-rounds/README.md)。复算器验证哈希及记录对应，拒绝重复有效评分和改变重试请求。工程测试数量不是质量分数。
