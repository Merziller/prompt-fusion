# 0.5.2-dev.0：草稿不变问题的本地修复候选

状态：**未发布的开发候选**。公开稳定版仍是 **0.5.1**。本记录不变更旧版成绩、历史发布附件或市场状态。

## 现象与证据

2026-11-27 对同一段真实输入点击 DSH 的“增强”：曾成功改写并出现“撤销增强”，也曾约 8.2 秒后回到“增强”，草稿未变。随后一次宿主工具响应返回 `engine: unchanged`、`failure.category: fidelity`，并非超时。没有每次点击对应的完整提供商返回记录，因此不把所有历史失败都归因于同一原因。

对已知输入的确定性复现证明了一个独立缺陷：旧机械检查将“声音不好听”“不舒服”等描述当作必须原样保留的禁止指令，并将“别扭”中的“别”识别为禁止标记。忠实同义改写因此可能被误拦。该测试先失败，修复后通过。模型仍可能产生真正不保真的结果；保留原稿的策略继续生效。

另有用户体验缺陷：失败原因只在鼠标悬停提示和屏幕阅读器文本中出现，视觉上表现为停止转圈、没有变化。

## 实现变化

- 区分有限的中文描述性谓语、普通词与真正的禁止指令。覆盖“不好听也不舒服”“听着别扭”“别人提交的代码”等已发现案例。
- 继续保护“别处理”“禁止扭曲”“别针对此事发表评论”“别称为定论”“不要替别人操作”等真实约束；歧义情形保守处理。
- 原单按钮、图标、基础样式和位置保留；在同一组件内增加可见的失败原因提示，不增加设置面板或第二个操作按钮。
- 增加保真、格式、网络、凭证、限流、超时、取消等有限类别。HTTP 408/504 优先按超时处理，接收 DSH 的结构化错误码。
- 清空草稿后，仍可点击正在工作的“停止”；组件中断有明确状态，手工编辑后清除旧提示。
- 失败诊断只记录 `modelCalls`、`lastStage`、`elapsedMs`、有限错误类别。提供商返回正文、密钥、任意错误消息不进入诊断。
- 不更改自动发送行为：增强器不执行提示词中的任务，不自动发送草稿。原有版本检查、引用坐标和撤销事务继续保留。

实现入口：[语义检查](../src/rewrite.mjs)、[失败分类](../src/failures.mjs)、[核心返回](../src/core.mjs)、[DSH 客户端源文件](../adapters/dsh/client-source.js)、[撤销状态](../adapters/dsh/undo-state.mjs)。

## 可复现命令

```sh
node scripts/build-client.mjs
node scripts/test-report.mjs
node scripts/check.mjs
npm pack --ignore-scripts --pack-destination output
node scripts/smoke-candidate.mjs --archive /absolute/path/candidate.tgz --npm-cli /absolute/path/npm-cli.js --sdk-root /absolute/path/node_modules/@modelcontextprotocol/sdk --deps-root /absolute/path/react-lexical-fixture
```

运行依赖仍为零。SDK 与 React/Lexical 仅用于验证，采用明确提供的本地目录，不作为安装后的运行依赖。候选验证在全新临时目录离线安装归档，逐文件比较已装字节，再运行完整测试、六种 SDK 组合及真实 React/Lexical 合同测试。其 Session 仍是显式测试桩，不冒称真实 DSH GUI。
