# 0.5.0-dev 本地候选：WorkBuddy 思路融合

状态：本地开发与评估，**尚未发布**。依用户要求，不提交或推送GitHub、不创建Release、不更新插件市场；先交付比较结果供确认。原0.4.0归档和历史评测保留，本候选不沿用其99.46分作为新成绩。

## 实际改动

1. **保守的自动轻量路径**：只考虑短、单意图、无数字/引号/代码/显式限制/多步关系的简单编辑请求。模型输出还必须通过既有保真检查和确定性的表面等价检查，才可在一次调用后返回。允许去掉开头礼貌词、整理空格和句末标点；不借此容许新增内容、同义替换、数字或条件变化。检查不通过就升级到原有审查流程，不直接应用。
2. **按原稿控制详略**：短请求倾向一段话；较复杂的请求只分必要组；长需求保留重要细节。不设统一800字符截断，也不把排版建议写成用户未提出的下游任务要求。
3. **明确网络反馈**：连接/代理/上游服务、超时、模型认证、限流、格式错误及保真检查分别识别。失败仍保留原草稿。反馈只暴露有界类别、HTTP状态和可重试标志，不展示供应商响应正文、凭证或私有URL。
4. **单按钮不变**：没有新增模式、强度、场景、语音或上下文选项。CSS、图标、位置及单控件数量沿用冻结基线；原生草稿版本校验、停止、撤销和会话切换保护仍在。
5. **统一核心**：DSH、CLI、MCP、REST与便携Skill共用新逻辑。Skill当前包含九个受回执管理的文件，并兼容旧五/六/七文件回执的核验卸载。

## 哪些没有照搬

- 不采用仅面向代码助手的全局身份。
- 不采用统一“不准代码片段/不准解释HOW”，仍按用户真实请求增强。
- 不强制任何原稿都必须有字面变化；明确原稿可以保持原样。
- 不硬性限制800字符或无条件截断长约束。
- 不让未通过检查的轻量输出跳过复核。

实现为独立代码，借鉴思路不等于取得文档所述WorkBuddy客户端源码或验证其内部行为。该文档系统模板与既有feiwell模板的文本重合另有记录；不据此推断复制方向、来源许可或整个产品等效。

## 使用与验证

需要Node.js ≥22.19.0。候选无运行时依赖。非DSH接口仅在显式`--model`后读取自备模型配置；没有模型时原文保留并返回警告。网络/服务可用性会影响真实测试，应与成功输出的内容质量分开看。

```sh
node scripts/build-client.mjs
node scripts/test-report.mjs
node scripts/check.mjs
node scripts/sdk-smoke.mjs --sdk-root /absolute/node_modules/@modelcontextprotocol/sdk
npm pack --ignore-scripts --pack-destination output
```

当前工程回归已完成341项通过，包含新增轻量路径、升级审查、网络分类及按钮反馈检查。独立SDK与候选归档的最新回执在实际执行后写入`output/`，不以工作区测试替代真实归档安装。

## 本轮五方对照

完整方法先于实现冻结，见[五方协议](evaluation/WORKBUDDY_INTEGRATION_PROTOCOL.md)：40条输入，三款原插件模板、WorkBuddy文档模板和本候选，共200份新生成记录；同一生成模型、温度和8192 token单次上限；每题匿名A—E正反两种顺序，五维总分100。多阶段调用成本另报，不声称等总token预算。

三款原插件只复现选定文本模板，不是其全部模式/原生UI/语音测试；WorkBuddy仅指用户所给文档模板，不是官方客户端实测。校准24题、前次新增8题和本轮专项8题分别报告，均为有目的构造样本，不能推断全部用户任务表现。

已保留200份生成记录：198份有效，2份对照模板遭遇上游服务错误，未重抽替换；所有40份本候选生成有效。评分端出现连接重置与服务熔断，按冻结规则仅补齐失败评审，保留所有尝试。**评分仍在收集，当前没有完整五方最终均分。** 报告将同时给出包含生成失败的可用性口径、共同成功样本的内容口径、延迟、调用次数和覆盖率。

用户说明前次两方比较中本候选的一次502源于网络代理连接故障。原记录不删除；新报告将注明用户解释，并区别服务可用性与文字质量。没有真实账单时不估算费用节省百分比。

## 边界

- 表面等价检查是狭窄的可验证快速路径，不是通用语义等价证明。
- 工程测试、协议替身、真实模型评分及厂商原生界面验证各自独立。尚未实测的原生客户端、登录态GUI或实体语音仍保持未验证。
- 本地候选安装通过不意味着发布门槛通过；旧0.4.0发行验证脚本保持原规则，不因新对照尚未完成而放宽。
