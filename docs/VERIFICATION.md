使用另行安装的`@modelcontextprotocol/sdk1.32.2`；产品运行时依赖仍为零。

## 真实模型四插件评测

[冻结协议](evaluation/OPTIMIZATION_PROTOCOL.md)：12条历史输入＋12条迁移输入；每轮四插件共96份新输出，匿名候选以两个顺序交给同一评审模型。五维权重为保真30、清晰25、相关补全20、简洁15、任务边界10。验收要求：两组均值各≥95，每条平均≥90，并且零关键错误。失败输出始终计零；格式/传输失败的评审只按原请求补齐，不重生成低分样本。

- 生成模型固定为`deepseek-official/deepseek-v4.1-flash`；三款原插件请求从已核实来源复现，输出上限4096 tokens，新核心8192 tokens，预算差异明确保留，不宣称完全等预算实验。
- 评审模型固定为`tokenshop/gpt-6-astra`。匿名和反向顺序减少位置影响，但它不是独立人工专家，也不是所有模型/任务的通用保证。
- 第一轮总体96.27，仍有七条关键问题，未通过。
- 第二轮总体91.00；两条生成失败计零，并有范围变化，未通过。
- 第三轮总体99.46、最低93.5；仍新增了“而不是先向我提问”，未通过。
- 第四轮总体62.17；34份四臂生成遭遇上游502，其中九份属于本插件；此外发现捏造用户尚未确定细节的关键问题，未通过。
- 第五轮总体99.10；最低94.5，但擅自规定周末复盘，未通过。原评审通道出现余额不足，恢复后仅补齐原请求的缺失评审；全部失败尝试保留。
- 第六轮总体98.85；固定集99.92、迁移集97.79、最低87.5。新增禁止得出结论、将“禁止选择技术”缩窄为“禁止自行选择技术”，未通过。
- 第七轮总体86.73；三个保真检查误报导致生成失败，另有超出按钮比较范围的新要求，未通过。失败仍计零。
- 第八轮总体99.38，固定集99.50、迁移集99.25、最低96；整封邮件长度被收窄为仅正文长度，关键错误仍阻断通过。
- 第九轮增加字数与适用对象关联检查、非排他职责保护。正确的“全文（含主题和正文）150字以内”被机械检查误拦；保留该失败，总体95.38、最低0，未通过。
- 第十轮修复整体范围中的括号包含关系，同时保持“仅正文”和后续明确正文限制检查。96份生成全部有效，48份有效匿名评审（另保留两次传输失败）。固定集99.79、迁移集99.13、总体99.46、最低单例95、关键错误0，**通过冻结验收**。当轮对照总均分分别为94.63、96.65、97.75。

十轮逐项比较和局限见[生成汇总](evaluation/RESULTS.md)。当时0.4.0运行时的十个模块与第十轮快照逐一比对，唯一允许变化为核心版本字面量；验证脚本为`node scripts/verify-release.mjs semantic-round-10`。同题迭代不是全新独立测试集；该分数不等同于任意场景的保证。

完整原始请求、输出、错误、评审、匿名映射、冻结运行时及SHA-256位于[逐轮证据目录](../evals/semantic-rounds/README.md)。离线复算示例：

```sh
node scripts/score-evaluation.mjs evals/semantic-rounds/semantic-round-03
```

新评测不删除[旧版质量审计](QUALITY_AUDIT.md)中约61分的问题记录。旧审计是作者另一量尺、新LLM调用为零的历史评审，不与新匿名模型评分混为同一数字。
