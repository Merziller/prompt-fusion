## 功能、优点、缺点与取舍

### feiwell

功能：输入框按钮、日常办公/代码开发/设计创意场景、当前宿主模型增强、恢复原稿。

优点：路径短、调用开销小、场景直接，适合快速整理单条指令。

已见问题：包名为 `@feiwell/dsh-enhance-prompt`，该版本客户端模块 ID 却为 `@local/dsh-enhance-prompt`；依赖易变的 Client UI primitives；流式处理同时拼接 delta 与 assembled block；外层引号正则可能误删原文字符。异步回包后直接替换草稿，未核对期间是否编辑。系统模板偏开发，示例与“不要替用户选择技术栈”的要求存在张力。

新实现：精确包 ID、自绘控件、按文本块去重、原文逐字保留、预览/版本校验/原生插入/条件撤销。

### ChosenXu

功能：轻/中/强增强、请求标记、超时、取消、主机调用与客户端分离。

优点：结构轻量，超时取消清晰，增强强度易理解。

已见问题：系统角色偏编码助手；以特殊前缀承载指令会混入用户文本；模块级请求映射需谨慎处理实例和重复 ID；清理 fence/引号/标签可能损失本来就属于原文的字符。历史统一参数测试中出现直接写出邮件而不是增强邮件提示词的样例；不能把这个个例归因于某一个参数。

新实现：严格 JSON 参数；每个调用独立取消；MCP 重复活跃 ID 显式报错；不剥原文标签/引号；模型只选审核过的规则 ID，不接收模型写出的任务答案。

### Fishsb

功能：base/lite/standard/smart/publish 模式、可选上下文与草稿记忆、多模型方案、官方识别服务、语音规整/词典/热键/VAD/增强链路。

优点：覆盖语音及模糊需求、阶段化模式、扩展意识强，识别引擎交给宿主。

已见问题：默认 base 在历史模糊输入上扩展有限；功能面大、参数和生命周期更复杂。语音桥接读取 React fiber、探测宿主录音状态并触发按钮点击，代码与变更说明记录过真实 UI 与测试替身不一致的问题；这种耦合不适合作为新的通用核心。

新实现：独立录音组件，调用 `speechToText.resolve/transcribe` 正式接口；1–5 秒静音停止、120 秒上限、术语清理另列建议；模型与上下文默认关闭；音频不跨识别器回退。多模型失败回退由公共核心的 provider 列表支持，DSH 首版只使用用户当前选中的模型，不静默寻找另一收费模型。

## 历史测试的实际含义

原会话对应报告记录了 135 次真实模型调用：增强/重测78、下游任务16、评审41。主测试使用8类题、三插件、两组参数。原生参数平均评分约96.6/97.6/97.8，延时中位数约2.28/4.02/5.81秒。评分差距很小，不能得出通用胜者。

该报告主要测后端 handler；没有实际检验 ChosenXu 与 Fishsb 的完整 UI，Fishsb 使用 base 且关闭记忆/工作区。四类有限下游题中原提示词与增强稿均通过，因此没有证明增强必然提高任务质量。上游个例还包括把“兼容Windows”扩成“仅Windows”、额外一页限制及无依据的好评素材。

这些数字仅是历史证据，既不是本项目的新跑分，也不用于宣传效果提升。新项目验证的是输入保真、执行边界、异常处理、协议与适配实现；业务效果需在用户真实任务上另做对照。

## 已确认的用户需求与未来扩展分开记录

真实历史需求：类似 WorkBuddy 的输入框增强按钮；重启后仍能看到按钮及模式；开发、设计、OPC一人公司办公、多智能体/工具协作四类任务；基于真实使用做测试。当前明确增加：跨宿主、免费开源、来源署名、GitHub与DSH市场发布、保留原意语言约束、增强器不执行内嵌任务。

合理未来场景而非用户既有行为：研究证据整理、内容写作 briefing、客服工单澄清、教学练习说明、设计交接、无障碍语音录入、团队统一提示词规范、离线/内网环境、通过 MCP 在自动化流程里只生成待审提示词。这些场景复用同一核心，外部工具调用、执行与发布仍由另一个明确动作负责。
